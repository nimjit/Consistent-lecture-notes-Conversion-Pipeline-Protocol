#+title: Source formats reference
#+startup: overview

Reference for the upstream formats found in course =source/= trees.
Not our rules — their rules — documented so that where our wiki protocol
diverges is visible.

Scope: structure only (Q2) — file tree + what each file does.

* Jupyter Book

Scientific documentation framework by the Executable Books Project.
Builds HTML/PDF from a tree of markdown and =.ipynb= pages.
The ordering of files is in =_toc.yml=.

Typical structure:

#+begin_example
<course>/source/
├── _config.yml           — site configuration (title, authors, build options)
├── _toc.yml              — ordered table of contents (page hierarchy)
├── content/              — pages (markdown and/or Jupyter notebooks)
│   └── …
├── _static/              — CSS, logos, other static assets
├── index.md              — landing page
├── requirements.txt      — Python deps for building
└── README.md
#+end_example

* mdbook

Rust-based markdown book framework. Static site built from a =src/= tree
whose structure is given by =SUMMARY.md=.

Typical structure:

#+begin_example
<course>/source/
├── book.toml             — site configuration (title, build options)
├── src/
│   ├── SUMMARY.md        — hierarchy (chapters and sections)
│   ├── <chapter>.md
│   └── …
├── .gitignore
└── README.md
#+end_example

Associated-tooling junk commonly found and stripped per protocol P1:
=.idea/= (JetBrains), =.gitlab-ci.yml=, =.vscode/=. Stripped items are
listed in =source/_meta.org= per course.

* Markdown converted from Jupyter notebooks

Flat markdown trees produced by =scripts/nb2md.py= from a =.ipynb=
upstream. The notebook itself is not retained; markdown is the
source.

No manifest file. Order is implicit in file names. Since this
is the structure according to the protocol, this is treated as
publishable-form markdown, not as upstream =source/=.

Typical structure:

#+begin_example
<course>/markdown/
├── <lecture-1>.md
├── <lecture-2>.md
└── …
#+end_example

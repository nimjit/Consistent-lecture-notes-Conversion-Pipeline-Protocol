#+title: Protocol — org-mode wiki
#+startup: overview

The authoritative rules for how org-mode material in this wiki is written
and organised. Sibling files:

- =protocol-markdown.org= — the public markdown mirror. Inherits every rule
  here except where it says otherwise. Currently a stub.
- =source-formats.org= — a *reference* describing the upstream formats found
  in =source/= trees (Jupyter Book, mdbook, …). Not governed by this
  protocol; this protocol only governs =org-mode/=.

Every rule carries a parenthesised code (A1, B3, …) back to the design
question that set it. The full decision ledger is at the end of this file.

* Status

Draft 1. The org-mode conversion works reasonably for LaTeX maths,
but still has issues converting cleanly without information-loss
to typst. markdown conversion is not yet handled, this will be
done if anyone other than me is actually interested in this conversion.

* Project layout

#+begin_example
Lecture Notes Wiki Project/
├── index.org               — generated: lists every course (K2)
├── courses.org             — the single course registry (licence-tracked)
├── tags.org                — controlled major-tag vocabulary (L1)
├── protocol/
│   ├── protocol-org.org    — this file
│   ├── protocol-markdown.org
│   └── source-formats.org
├── scripts/
│   ├── nb2md.py            — notebook → markdown
│   ├── pull-courses.sh     — one-off upstream fetch
│   ├── preamble.typ        — project-wide Typst macros (F4)
│   ├── gen-index.*         — index generators (K1, K2)
│   └── lint.*              — the lint script (O1)
├── <domain>/               — physics/, computing/, mathematics/, …
│   └── <course-slug>/
│       ├── README.org
│       ├── source/         — upstream verbatim (optional)
│       ├── org-mode/       — the org wiki form (optional)
│       └── markdown/       — the markdown mirror (optional)
└── …
#+end_example

Courses are grouped by *domain* (A1). A domain directory holds nothing
but course directories. The project-wide =index.org= is generated by a
script and should never be edited by hand (K2).

Protocol files live in =protocol/= (A4). Tooling lives in =scripts/= (A3).

* Per-course layout

A course directory can contain any of three subdirectories; all are
optional (B1 — fixed names, extras allowed). Which are present depends
on the course's provenance:

| Subdir    | Purpose                                                           |
|-----------+-------------------------------------------------------------------|
| =source/=   | Upstream material (mdbook, Jupyter Book, notebooks, …), verbatim. |
| =org-mode/= | The org wiki form. The primary artifact; what you edit.           |
| =markdown/= | The markdown mirror. Future public form, or direct nb→md output.  |

A =README.org= at the course root is the single source of truth for
course-level metadata (B2): course name, short code, upstream URL,
licence, status.

Inside =org-mode/=:

#+begin_example
<course>/org-mode/
├── index.org              — generated course TOC (K1)
├── lectures/
│   └── <short>-NN-slug.org
├── assignments/            — optional
│   └── <short>-NN-assignment.org
└── assets/
    ├── attachments/        — figures, diagrams, images (H1)
    └── code/               — mirrored course-shipped code (B4, H1)
#+end_example

Lectures and assignments live in separate subtrees (B3). The =assets/=
directory splits attachments and code (H1).

* File naming

Lowercase, hyphenated, full words — everywhere (C4). Reasons:

- URL-safe when the wiki is published (no spaces, no case issues)
- Case-insensitive-filesystem-safe (macOS defaults, Windows)
- No shell escaping or quoting
- Git-, static-site-generator- and Obsidian-friendly

** Course folders (C5)

Format: =<domain>/<course-slug>/= where =<course-slug>= is the course
title as a lowercase hyphenated slug.

Example: =physics/classical-mechanics-and-special-relativity/=.

** Lecture / assignment files (C1, C2)

Pattern: =<short>-NN-slug.org=.

- =<short>= — the course's short code, declared in the course =README.org=.
  Short codes are what make the filename self-identifying when a file is
  moved out of its tree. Lowercase hyphenated, per C4. Examples: =cmsr=,
  =comp-phys=, =sf=, =oop-cpp=.

  When two courses would collide at the obvious abbreviation
  (/Applications of Quantum Mechanics/ and /Advanced Quantum Mechanics/
  would both want =aqm=), disambiguate explicitly: =ap-qm= and =ad-qm=.
  Resolve the collision when adding the second course; do not rename the
  first retroactively unless the collision has shipped.
- =NN= — zero-padded 2-digit number (C2). Enough for every course we expect.
- =slug= — a short slug (1–5 words) derived from the lecture title.

Multi-part lectures use letter suffixes: =<short>-04a-slug.org= and
=<short>-04b-slug.org= (C3).

Assignments are *lecture-aligned* (I3). The assignment for lecture =NN=
uses the matching number: =<short>-NN-assignment.org= (the slug may
differ from the lecture's).

* Frontmatter

Every lecture or assignment file carries at minimum (E1):

#+begin_src org
:PROPERTIES:
:ID:           <org-id, used as the roam id (J1, J5)>
:COURSE:       <full course name>
:COURSE_SHORT: <short code>
:TYPE:         lecture | assignment | own-notes
:NUMBER:       <int, matching filename>
:PREV:         <id or empty>
:NEXT:         <id or empty>
:STATUS:       stub | draft | clean
:TAGS:         <space-separated tag list>
:END:
#+end_src

Licence and upstream URL are *per course only* (E3, M1); they live in
the course =README.org=, never on individual files. =TYPE: own-notes=
flags a file written by the author while attending a course (M2); the
=README.org= names the author and course context.

* Section structure of a lecture note

Required top-level sections (D1):

1. =Prev. lecture= — a human-visible section rendering the PREV link.
2. =Content= — the lecture body.
3. =Summary= — see below.
4. =Next lecture= — human-visible section rendering the NEXT link.

Prev/next appear both in frontmatter and as sections (D2). The sections
exist for human readers; the frontmatter exists for tooling.

** Summary subsection shape (D4)

The Summary section contains, in order:

1. *Recap* — 3–5 bullet points.
2. *Concepts introduced* — a list of named concepts for later
   cross-linking. One phrase per line.

* Definitions, theorems, proofs

Marked with custom org blocks (D3):

#+begin_example
#+BEGIN_definition <name>
...
#+END_definition

#+BEGIN_theorem <name>
...
#+END_theorem

#+BEGIN_proof <of what>
...
#+END_proof
#+end_example

The name after the keyword is the human-readable label; renderers can
show it and the lint/build scripts can index it.

* Maths — Typst

The wiki writes math in *Typst syntax* and nothing else (F3). LaTeX in
the org tree is forbidden; LaTeX found in imported upstream is converted
at import time.

- Inline: =$x^2$= — content flush against the delimiters.
- Block: =$ x^2 $= — content spaced from the delimiters (Typst's
  convention for display math).

A project-wide =scripts/preamble.typ= holds every macro / command
definition (F4) and is imported by the Typst build.

Renderer note. The primary consumer is the author's Emacs Typst renderer.

** Known conversion limitations

Residual LaTeX that =scripts/convert/= doesn't yet translate cleanly;
pass over converted files and fix by hand, or extend the Lua filter at
=scripts/convert/lua/latex-to-typst.lua=:

- *Vector / operator ornaments.* The converter emits Typst primitives
  directly: =arrow(x)= for =\vec{x}=, =bold(x)= for =\mathbf{x}=,
  =hat(x)= for =\hat{x}=, =bb(R)= for =\mathbb{R}=, =cal(X)= for
  =\mathcal{X}=. No =scripts/preamble.typ= dependency; the output
  renders standalone. (Earlier versions emitted =vb(x)= / =op(x)= / =RR=
  that relied on preamble aliases; those have been retired.)
- *=\begin{…}= / =\end{…}= environments.* LaTeX math environments
  (=aligned=, =pmatrix=, =bmatrix=, =array=, =cases=, …) survive as
  literal text because the Lua filter is name-level, not
  environment-aware. Convert to Typst =mat()= / =cases()= / aligned
  blocks by hand until the filter is extended.
- *Other unknown macros* get stubbed to their bare name (e.g. =\text=
  → =text=) with the backslash stripped. Grep converted files for
  =\\[A-Za-z]+= to find them; add to the KNOWN table in the Lua filter
  when a pattern recurs.
- *Implicit multiplication of single letters.* LaTeX relies on math-mode
  auto-spacing to render =\int fdz= as "∫ f d z". After conversion the
  three letters stay fused as the single Typst identifier =fdz=.
  There is no safe heuristic to split (not every =foo= is three
  variables), so clean these by hand to =f d z= or =f dif z=.

* Code blocks

- Language annotation is *required* on every block (G1):
  =#+BEGIN_SRC rust=.
- Snippets are executable via org-babel where sensible (G2). Larger
  curriculum code lives as files under =org-mode/assets/code/= (B4).
- =#+RESULTS= blocks are *not stored* (G3). Readers run the code.

* Assets

** Layout

#+begin_example
<course>/org-mode/assets/
├── attachments/   — figures, diagrams, images (H1)
└── code/          — course-shipped example code (B4, H1)
#+end_example

** Naming and reference form (H2)

File names are descriptive slugs (e.g. =feynman-diagram-tree-level.svg=),
not tied to the lecture number. Lecture files reference assets by
relative file path:

#+begin_example
[[file:../assets/attachments/feynman-diagram-tree-level.svg]]
#+end_example

This renders inline in Emacs via =C-c C-x C-v= (=org-toggle-inline-images=)
without any project-level configuration. Chosen over =[[attachment:…]]=
because the latter requires wiring =org-attach= to the shared
=assets/attachments/= dir, and because the id-stability justification the
=attachment:= form was meant to provide isn't actually delivered when the
link uses the filename rather than the attachment id.

** Captions (H3)

A =#+CAPTION:= line immediately above the =[[file:…]]= link is *required
for figures sourced from externally-licenced material*. Captions on
original figures are optional but encouraged. Add =#+NAME:= by hand only
when a figure needs to be cross-referenced from within the same file.

** No PDFs in the wiki (H4)

Lecture notes do not store or link to local PDFs of textbooks or papers.
External works are referenced by *URL only* — a =doi.org= link, publisher
page, arXiv link, etc. Local PDF libraries live elsewhere
(=~/org/library/=) and are not linked from inside the wiki.

* Assignments

Dedicated template (I1):

#+begin_src org
;* Problem statement
...

;* Solution
...

;* Reflection
...
#+end_src

Both the assignments subtree itself and the =* Solution= section are
optional (I2). A course without assignments has no =assignments/=
subdirectory. An assignment file may omit =* Solution= when the course
distributes an official solution; link to it from =* Reflection= instead.

* Links

| Target                           | Form                           | Rule            |
|----------------------------------+--------------------------------+-----------------|
| Lecture → lecture (same course)  | =[[id:...][...]]=                | J1              |
| Lecture → lecture (cross-course) | =[[id:...][...]]=                | J3; discouraged |
| Section inside a file            | =[[file:<path>::*Heading][...]]= | J2              |
| External resource                | plain URL                      | J4              |

Backlinks are tracked by *org-roam* (J5). Every lecture and assignment
file is an org-roam node; the file's =:ID:= is also its roam id.

Cross-course links use the same =id:= form as intra-course links but are
*discouraged* in v1: use them only where a concept genuinely spans
courses, not for incidental mentions.

* Tags

** Vocabulary (L1)

- *Major tags* — declared in =tags.org= at the project root. A controlled
  set, enforced by the linter.
- *Minor tags* — free-form, grown by use.

** Spelling rules (L1)

Every tag — major or minor — is written as *full words, lowercase,
hyphenated*. The linter rejects abbreviations, capitals, and underscores.

** Scope (L2)

Standard org tag inheritance. File-level tags apply to every heading;
headings may add tags that apply to themselves and descendants.

* Indices

- Per-course =index.org= — generated from the file list + frontmatter (K1).
  The course =README.org= names the course; =index.org= is the navigation
  tree.
- Project-wide =index.org= at the root — generated from the per-course
  =README.org= files (K2).

Both generators are scripts under =scripts/=. Do not hand-edit either
index file.

* Treatment of =source/= (upstream)

- =source/= is a *verbatim mirror* (P1) and a *frozen snapshot* (P2).
- No edits — not even stripping IDE junk or OS metadata. Live with the
  clutter.
- Upstream URL, licence, author attribution, import date all live in the
  course =README.org= (B2, M1). Nothing is added inside =source/=.
- There is no sync workflow (P2). To update a course, replace =source/=
  wholesale.

* Build to markdown

Generator deferred (N1). When filled in, see =protocol-markdown.org=.

- Builds run *on demand* (N2) — no automatic git hook, no CI (yet).
- The Obsidian vault form mirrors the org tree exactly (N3): same
  folders, same filenames with =.md= extension.

* Linting

Form: both a prose checklist (this section) and an executable script
under =scripts/= that implements it (O1).

Checks (O2):

- *Frontmatter completeness* — every required field (E1) is present on
  every lecture / assignment file. Covers "licence recorded" implicitly:
  the file's =COURSE= points at a =README.org= with a =LICENCE=.
- *Working links* — every =id:= and =file:= link resolves.
- *Required sections present* — Prev. lecture / Content / Summary /
  Next lecture on every lecture file (D1).
- *Filename ↔ frontmatter* — the filename pattern =<short>-NN-slug= agrees
  with =COURSE_SHORT= and =NUMBER= in the file's frontmatter; =TYPE=
  matches which subtree the file is in.
- *Tag discipline* — every tag is lowercase, hyphenated, full words; every
  major tag appears in =tags.org=.

#+title: Protocol — org-mode wiki
#+startup: overview

* Scope

This document specifies the org-mode form of the lecture-notes wiki:
directory layout, file naming, per-file metadata, section structure, and
the conventions for maths, code, assets, links and tags. It is the
authoritative reference for *producers* (authors and converters) and
*consumers* (the linter, index generators, org-roam, Markdown builders).

It specifies what a conforming wiki looks like. It does not specify
tooling.

Sibling documents:

- =protocol-markdown.org= — the public Markdown mirror. Inherits every
  rule here except where it says otherwise. Currently a stub.
- =source-formats.org= — informative reference for the upstream formats
  found in =source/= trees (Jupyter Book, mdBook, …). Not governed by this
  protocol; this protocol governs =org-mode= only.

Document status: protocol version 1, draft 2. See [[*Revision history]].

* Conventions

** Requirement levels

The words MUST, MUST NOT, REQUIRED, SHOULD, SHOULD NOT and MAY, when
written in upper case, are to be interpreted as in RFC 2119. In lower
case they carry their ordinary meaning.

** Codes and rule IDs

Every rule carries a parenthesised /ledger code/ (A1, D3, …) tracing it
to the [[*Decision ledger]]. Checks in [[*Conformance levels]] carry /rule
IDs/ (NAM-01, SEC-02, …).

** Notation

- =<angle brackets>= mark a placeholder.
- =a | b= marks alternatives.
- Grammars use ABNF (RFC 5234).
- Paragraphs beginning /Note./ are non-normative.

* Terminology

| Term            | Meaning                                                                                      |
|-----------------+----------------------------------------------------------------------------------------------|
| wiki            | The whole project tree.                                                                      |
| domain          | A top-level directory grouping courses (=physics/=, …).                                        |
| course          | A directory =<domain>/<course-slug>/=.                                                         |
| lecture file    | A file with =:TYPE: lecture=.                                                                  |
| assignment file | A file with =:TYPE: assignment=.                                                               |
| node            | A file as seen by org-roam. Every lecture, assignment and own-notes file is a node (J5).     |
| producer        | A person or tool that writes files.                                                          |
| consumer        | A tool that reads files.                                                                     |
| dialect         | The maths syntax a file uses: =latex= or =typst= (F5).                                           |
| level           | A conformance level, 0 to 2 (O3).                                                            |

* Version and extensibility

** Protocol version (R1)

This document defines protocol version 1. A course =README.org= SHOULD
declare the version it conforms to in =:PROTOCOL:=. A consumer MUST treat
an absent =:PROTOCOL:= as =1=. A backward-incompatible change increments
the integer; a compatible addition does not.

** Unknown properties (R2)

A consumer MUST ignore properties it does not define and MUST preserve
them when it rewrites a file. A producer MAY add properties; their names
SHOULD be upper case with underscores. A producer MUST NOT reuse a
property name defined here with a different meaning.

* Project layout

#+begin_example
Lecture Notes Wiki Project/
├── index.org               — generated: lists every course (K2)
├── courses.org             — generated course registry, licence-tracked (A2)
├── tags.org                — controlled major-tag vocabulary (L1)
├── protocol/               — this protocol and its siblings (A4)
├── scripts/                — tooling; not part of the protocol (A3)
├── <domain>/               — physics/, computing/, mathematics/, …
│   └── <course-slug>/
└── …
#+end_example

- A domain directory MUST contain only course directories (A1).
- =index.org= and =courses.org= are generated. They MUST NOT be edited by
  hand (K2).
- A project-wide =scripts/preamble.typ= MAY define Typst macros (F4).

* Per-course layout

A course directory has this shape:

| Entry                               | Req. | Purpose                                    |
|-------------------------------------+------+--------------------------------------------|
| =README.org=                          | MUST | Course-level metadata. See [[*Course README]]. |
| =source/=                             | MAY  | Upstream material, verbatim.               |
| =org-latex/= or =org-typst=             | MAY  | The org wiki form.                         |
| =markdown-latex/=  or =markdown-typst/= | MAY  | The Markdown form.                         |

The three subdirectory names are fixed. A course MAY contain other
entries, which consumers MUST ignore (B1).

Inside =org-latex/=:

#+begin_example
<course>/org-latex/
├── index.org              — generated course table of contents (K1)
├── lectures/
│   └── <short>-NN-slug.org
├── assignments/           — present only if the course has assignments
│   └── <short>-NN-assignment.org
└── assets/
    ├── attachments/       — figures, diagrams, images (H1)
    └── code/              — course-shipped code, mirrored (B4, H1)
#+end_example

- Lecture files and own-notes files MUST be in =lectures/=. Assignment
  files MUST be in =assignments/= (B3, M2).
- A course without assignments MUST NOT have an =assignments/= directory
  (I2).
- =org-latex/index.org= is generated and MUST NOT be edited by hand (K1).

** Course README

=README.org= at the course root is the single source of truth for
course-level metadata (B2, E2, E5). The metadata is in a file-level
property drawer:

| Property        | Req.                         | Value                                              |
|-----------------+------------------------------+----------------------------------------------------|
| =:COURSE:=        | MUST                         | Full course name.                                  |
| =:COURSE_SHORT:=  | MUST                         | Short code (see [[*File naming]]).                   |
| =:STATUS:=        | MUST                         | =stub \vert draft \vert clean=; see [[*Status (S1, S2)]]. |
| =:PROTOCOL:=      | SHOULD                       | Protocol version (R1).                             |
| =:UPSTREAM_URL:=  | MUST if the course has an upstream | URL of the upstream repository.              |
| =:LICENCE:=       | MUST                         | An SPDX licence identifier where one exists.       |
| =:AUTHOR:=        | MUST                         | Upstream author or origin; for own-notes the notes' author (M2). |
| =:IMPORTED:=      | MUST if =source/= exists       | Import date, ISO 8601.                             |

The body of =README.org= is free-form.

* File naming

All file and directory names are lowercase, hyphenated, full words (C4).

/Note./ This keeps names URL-safe, safe on case-insensitive filesystems
(macOS and Windows defaults), free of shell quoting, and friendly to Git,
static-site generators and Obsidian.

** Course directories (C5)

=<course-slug>= is the course title as a lowercase hyphenated slug.
Example: =physics/super-duper-advanced-quantum-quantum-quantum/=.

** Lecture, own-notes and assignment files (C1, C2, C3, C6)

#+begin_example
lecture-file    = short "-" number [ part ] "-" slug ".org"
assignment-file = short "-" number "-assignment.org"
short           = word *( "-" word )     ; the declared :COURSE_SHORT:
number          = 2DIGIT                 ; zero-padded
part            = %x61-7A                ; one lowercase letter, multi-part lectures
slug            = word *4( "-" word )    ; 1 to 5 words
word            = 1*( %x61-7A / DIGIT )  ; lowercase ASCII letters and digits
#+end_example

- =short= is the course's short code, declared in the course
  =README.org=. It makes a filename self-identifying when a file is moved
  out of its tree. And improves legibility of filenames for long course names.
  Examples: =cmsr=, =comp-phys=, =sf=, =oop-cpp=.
- =short= MUST be unique across the wiki. When two courses would collide
  at the obvious abbreviation (/Applications of Quantum Mechanics/ and
  /Advanced Quantum Mechanics/ both want =aqm=), disambiguate explicitly:
  =ap-qm= and =ad-qm=. Resolve the collision when adding the second
  course; do not rename the first unless the collision has shipped.
- Multi-part lectures use letter suffixes: =<short>-04a-slug.org=,
  =<short>-04b-slug.org=.
- Assignments are lecture-aligned (I3): the assignment for lecture =NN=
  is =<short>-NN-assignment.org=. Its slug is always =assignment=, whatever
  the lecture's slug is.

Valid: =cmsr-04-lagrangian-mechanics.org=, =cmsr-04a-noether-theorem.org=,
=comp-phys-12-monte-carlo.org=. Invalid: =CMSR-04-x.org= (case),
=cmsr-4-x.org= (width), =cmsr-04-lagrangian_mechanics.org= (underscore).

** Sequence order (C7)

Files of one =TYPE= within a course are ordered by =number= (numeric),
then by =part= (absent before =a=, then alphabetical). =:PREV:= and
=:NEXT:= follow this order.

* Frontmatter

Every lecture, own-notes and assignment file MUST begin with a file-level
property drawer, followed by a =#+title:= keyword (E4):

#+begin_src org
:PROPERTIES:
:ID:           <org-id>
:COURSE:       <full course name>
:COURSE_SHORT: <short code>
:TYPE:         lecture | assignment | own-notes
:NUMBER:       <int>
:PREV:         <id or empty>
:NEXT:         <id or empty>
:STATUS:       stub | draft | clean
:TAGS:         <space-separated tag list>
:MATH_FORMAT:  latex | typst
:END:
#+title: <title>
#+end_src

| Property       | Req. | Constraint                                                                                          |
|----------------+------+-----------------------------------------------------------------------------------------------------|
| =:ID:=           | MUST | An org-id, unique across the wiki. Also the org-roam id (J1, J5). Once assigned it MUST NOT change. |
| =:COURSE:=       | MUST | Equal to the course =README.org= =:COURSE:=.                                                            |
| =:COURSE_SHORT:= | MUST | Equal to the course =README.org= =:COURSE_SHORT:= and to the filename's =short=.                          |
| =:TYPE:=         | MUST | Lecture, Assignment, or own-notes. Agrees with the subtree (B3, M2).                                |
| =:NUMBER:=       | MUST | Integer equal to the filename's =number=, without the =part= suffix.                                    |
| =:PREV:=, =:NEXT:= | MUST | The =:ID:= of the adjacent file of the same =TYPE= (C7), or empty at the ends of the chain.             |
| =:STATUS:=       | MUST | Stub, draft, or clean. See [[*Status (S1, S2)]].                                                        |
| =:TAGS:=         | MUST | Space-separated tags; MAY be empty. See [[*Tags]].                                                      |
| =:MATH_FORMAT:=  | MUST | Latex, or Typst. See [[*Maths]]. (F5).                    |

Licence and upstream URL are recorded per course in the course
=README.org=, which is authoritative (E3, M1). A producer MAY copy
=:LICENCE:=, =:UPSTREAM_URL:= and =:AUTHOR:= into a file's drawer for
portability. Where present they MUST agree with the course
=README.org=, which prevails on disagreement.

=:TYPE: own-notes= flags a file written by the author while attending a
course (M2). Own-notes files follow every rule for lecture files.

* Section structure of a lecture file

Lecture and own-notes files MUST have these top-level headings, with
exactly this text, in this order (D1):

| # | Heading           | Content                                              |
|---+-------------------+------------------------------------------------------|
| 1 | =Prev. lecture=     | A rendering of the =:PREV:= link.                      |
| 2 | =Content=           | The lecture body.                                    |
| 3 | =Summary=           | See below.                                           |
| 4 | =Next lecture=      | A rendering of the =:NEXT:= link.                      |

** Prev/next sections and boundary sentinels (D2)

Prev/next appear both as properties, for tooling, and as sections, for
human readers.

- If =:PREV:= is non-empty, the =Prev. lecture= body MUST contain a link
  =[[id:<PREV>][<title>]]=. If it is empty, the body MUST contain the text
  =(first lecture)=. The text =(first lecture)= MUST NOT appear otherwise.
- If =:NEXT:= is non-empty, the =Next lecture= body MUST contain a link
  =[[id:<NEXT>][<title>]]=. If it is empty, the body MUST contain the text
  =(last lecture)=. The text =(last lecture)= MUST NOT appear otherwise.

** Summary (D4)

=Summary= MUST contain two second-level headings, in order:

1. =Recap= — 3 to 5 bullet points.
2. =Concepts introduced= — a list of named concepts for later
   cross-linking, one phrase per list item.

/Note./ Upstream notes do not contain summaries or concept lists, so a
converter cannot create them. They are written by hand, and =:STATUS:=
records how far a file has got.

* Definitions, theorems, proofs (D3)

Marked with custom org blocks:

#+begin_example
#+BEGIN_definition <name>
...
#+END_definition

#+BEGIN_theorem <name>
...
#+END_theorem

#+BEGIN_proof <of what>
...
#+END_proof
#+end_example

- The block type is lowercase: =definition=, =theorem=, =proof=. =BEGIN= and
  =END= MUST match.
- =definition= and =theorem= blocks MUST have a name. A =proof= block
  SHOULD name what it proves.
- The text after the keyword is the human-readable label. Renderers MAY
  show it and tools MAY index it.

* Maths

** Dialects (F5)

A file's maths is written in exactly one dialect, declared by
=:MATH_FORMAT:=. A file MUST NOT use the delimiters of the other dialect.

| Dialect | Inline (F1)             | Display (F2)               |
|---------+-------------------------+----------------------------|
| =latex=   | =\(x^2\)=                 | =\[ x^2 \]=                  |
| =typst=   | =$x^2$=                   | =$ x^2 $=                    |

** =latex= (default)

- Inline math MUST use =\(…\)= and display math =\[…\]=. The dollar
  delimiters =$…$= and =$$…$$= MUST NOT be used as math delimiters.
- Display math MAY use LaTeX environments (=\begin{align}…\end{align}=).

** =typst=

- Inline math is delimited by =$= with the content flush against both
  delimiters: =$x^2$=.
- Display math is delimited by =$= with whitespace (a space or newline)
  after the opening and before the closing delimiter: =$ x^2 $=.
- Whitespace on only one side is malformed and MUST NOT occur.
- A =typst= file MUST NOT contain LaTeX math delimiters or environments
  (F3).

** Macros (F4)

A project-wide =scripts/preamble.typ= MAY define Typst macros and is
imported by the Typst build. A converter MUST emit Typst that renders
without it.

** Converting between dialects (F3)

LaTeX found in imported upstream material MAY be converted to =typst= at
import time. A producer that does so MUST set =:MATH_FORMAT: typst=. A
producer that does not convert MUST set =:MATH_FORMAT: latex=.

* Code blocks (G1, G2, G3, B4)

- Every source block MUST name its language: =#+BEGIN_SRC rust= (G1).
- Snippets SHOULD be executable via org-babel where sensible (G2).
- =#+RESULTS= blocks MUST NOT be stored (G3). Readers run the code.
- Larger curriculum code lives as files under =org-mode/assets/code/=
  (B4).

* Assets

** Layout (H1)

Figures, diagrams and images are in =org-mode/assets/attachments/=.
Course-shipped code is in =org-mode/assets/code/=.

** Naming and reference form (H2)

File names are descriptive slugs (C4), such as
=feynman-diagram-tree-level.svg=, and are not tied to the lecture number.
Lecture files MUST reference assets by relative file path:

#+begin_example
[[file:../assets/attachments/feynman-diagram-tree-level.svg]]
#+end_example

/Note./ This renders inline in Emacs via =C-c C-x C-v=
(=org-toggle-inline-images=) with no project configuration. It is chosen
over =[[attachment:…]]=, which requires wiring =org-attach= to the shared
=assets/attachments/= directory, and whose id-stability benefit is not
delivered when the link uses a file name rather than an attachment id.

** Captions (H3)

A =#+CAPTION:= line immediately above the =[[file:…]]= link is REQUIRED
for every figure in a file whose course has an =:UPSTREAM_URL:=, unless
the file's =:TYPE:= is =own-notes=. Elsewhere captions are OPTIONAL but
encouraged. =#+NAME:= SHOULD be added only when a figure is
cross-referenced from within the same file.

** No PDFs (H4)

Files MUST NOT store or link to local PDFs of textbooks or papers.
External works are referenced by URL only: a =doi.org= link, publisher
page, arXiv link, etc. Local PDF libraries live outside the wiki.

* Assignments (I1, I2, I3)

An assignment file MUST have these top-level headings, in this order:

| Heading               | Req.   |
|-----------------------+--------|
| =Problem statement=     | MUST   |
| =Solution=              | MAY    |
| =Reflection=            | MUST   |

An assignment MAY omit =Solution= when the course distributes an official
solution; =Reflection= SHOULD then link to it. Assignments are
lecture-aligned (I3).

* Links

| Target                           | Form                              | Code            |
|----------------------------------+-----------------------------------+-----------------|
| Lecture → lecture (same course)  | =[[id:<ID>][<text>]]=               | J1              |
| Lecture → lecture (cross-course) | =[[id:<ID>][<text>]]=               | J3; discouraged |
| Section inside a file            | =[[file:<path>::*Heading][<text>]]= | J2              |
| External resource                | plain URL                         | J4              |

- Backlinks are tracked by org-roam (J5). Every lecture, assignment and
  own-notes file is a node, and its =:ID:= is its roam id.
- Cross-course links are discouraged in version 1. Use them only where a
  concept genuinely spans courses, not for incidental mentions.

* Tags

** Vocabulary (L1)

- *Major tags* are declared in =tags.org= at the project root, which is the
  authoritative list. Adding a major tag is a protocol change.
- *Minor tags* are free-form and grown by use.

** Spelling (L1)

Every tag, major or minor, MUST match:

#+begin_example
tag  = word *( "-" word )
word = 1*( %x61-7A / DIGIT )
#+end_example

Tags SHOULD be full words, not abbreviations.

** Scope and org syntax (L2)

Standard org tag inheritance applies. File-level tags apply to every
heading; headings MAY add tags that apply to themselves and their
descendants.

Org tag syntax does not permit hyphens. In org tag position (=#+FILETAGS:=
or a heading's =:tag:= suffix), =-= is written =_=, and =a_b= denotes the
same tag as =a-b=. The =:TAGS:= property uses the hyphenated spelling.

* Indices (K1, K2)

- The per-course =org-mode/index.org= is generated from the file list and
  frontmatter. The course =README.org= names the course; =index.org= is the
  navigation tree.
- The project-wide =index.org= is generated from the per-course
  =README.org= files.
- An index MUST NOT be edited by hand.

* Treatment of =source/= (P1, P2, M1)

- =source/= is a verbatim mirror (P1) and a frozen snapshot (P2).
- Nothing in it may be edited, including IDE junk and OS metadata.
- Upstream URL, licence, author and import date are recorded in the course
  =README.org= only. Nothing is added inside =source/=.
- There is no sync workflow. To update a course, replace =source/=
  wholesale.

* Build to Markdown (N1, N2, N3)

The generator is deferred (N1); see =protocol-markdown.org=.

- Builds run on demand (N2): no automatic hook, no CI.
- The Obsidian vault form mirrors the org tree exactly (N3): the same
  folders and file names, with the =.md= extension.

* Conformance levels

** Status (S1, S2)

=:STATUS:= records the conformance level a file claims:

| =:STATUS:= | Level | Meaning                                    |
|----------+-------+--------------------------------------------|
| =stub=     |     0 | Addressable: valid paths, metadata, links. |
| =draft=    |     1 | Structurally complete.                     |
| =clean=    |     2 | Verified and cross-linked.                 |

Levels are cumulative: level 1 includes every rule of level 0, and level 2
every rule of levels 0 and 1.

- A file declaring =:STATUS: s= MUST satisfy every rule of level(s) and
  below. A producer MUST NOT write a =:STATUS:= whose rules the file does
  not satisfy.
- A course's =:STATUS:= (in its =README.org=) MUST NOT be higher than the
  lowest =:STATUS:= among its files (S2).

** Rules (O3)

| ID     | Level | Requirement                                                                                                    | Code       |
|--------+-------+----------------------------------------------------------------------------------------------------------------+------------|
| LAY-01 |     0 | The course directory is =<domain>/<course-slug>/=, has a lowercase hyphenated slug.                              | A1, B2, C5 |
| LAY-02 |     0 | Lecture and own-notes files are in =lectures/=; assignment files are in =assignments/=.                            | B3, M2     |
| NAM-01 |     0 | The file name matches the grammar in [[*File naming]], using the declared =short=.                                   | C1, C2, C3 |
| NAM-02 |     0 | The file name agrees with =:COURSE_SHORT:= and =:NUMBER:=; the subtree agrees with =:TYPE:=.                         | O2         |
| FRM-01 |     0 | A file-level drawer is present with every REQUIRED property, followed by =#+title:=.                             | E1, E4     |
| FRM-02 |     0 | =:ID:= values are unique across the wiki.                                                                        | E1         |
| FRM-03 |     0 | =:TYPE:=, =:STATUS:= and =:MATH_FORMAT:= hold permitted values.                                                      | E1, F5     |
| FRM-04 |     0 | =:COURSE:= and =:COURSE_SHORT:= agree with the course =README.org=.                                                  | E2         |
| FRM-05 |     0 | The course =:STATUS:= is not higher than the lowest file =:STATUS:=.                                               | S2         |
| MTH-01 |     0 | A file contains only the maths delimiters of its declared dialect.                                             | F1, F2, F5 |
| AST-01 |     0 | Every =[[file:…]]= link resolves to an existing file.                                                            | H2         |
| SEC-01 |     1 | Lecture and own-notes files have the four required headings, in order.                                         | D1         |
| SEC-02 |     1 | The boundary-sentinel rules hold.                                                                              | D2         |
| SEC-03 |     1 | =Summary= contains =Recap= then =Concepts introduced=.                                                               | D4         |
| SEC-04 |     1 | Assignment files have =Problem statement= and =Reflection=, with =Solution= between them if present.                 | I1, I2     |
| BLK-01 |     1 | Custom blocks have matching =BEGIN=/=END= and a name where required.                                             | D3         |
| COD-01 |     1 | Every source block names a language.                                                                           | G1         |
| TAG-01 |     1 | Every tag matches the spelling grammar.                                                                        | L1         |
| LNK-01 |     2 | Every =[[id:…]]= link resolves to a node.                                                                        | J1         |
| LNK-02 |     2 | =:PREV:= and =:NEXT:= are reciprocal, and follow the sequence order.                                               | D2, C7     |
| TAG-02 |     2 | No tag is a near-miss spelling of a major tag in =tags.org= (equal after lowercasing and removing "-,_, ").      | L1         |
| AST-02 |     2 | Every figure carries =#+CAPTION:= where [[*Captions (H3)]] requires it.                                              | H3         |
| MTH-02 |     2 | A =typst= file has no residual LaTeX: no =\begin{…}= and no =\<letters>= command in maths.                           | F3         |

** Linter behaviour (O3, S3, O4)

- =lint --level N= checks every file against all rules of level N and
  below, regardless of =:STATUS:=.
- =lint= with no level checks each file against the level of its own
  =:STATUS:= (S3).
- A diagnostic SHOULD be reported as =<path>:<line>: <rule-id>: <message>=
  (O4).

* Reserved for later revisions

The following are unspecified in version 1. Producers MUST NOT assume a
behaviour for them.

- Block types beyond =definition=, =theorem= and =proof=, and body
  normalisation (whitespace, auto-fix versus reject) (D3, D4).
- Language-specific rules for code blocks that must work together (G2).
- The Markdown mirror (N1).

* Revision history

** Draft 2

Changed:

- *Maths (F1–F4).* The protocol is no longer Typst-only. Each file declares
  =:MATH_FORMAT:= (=latex=, the default, or =typst=) and uses that
  dialect's delimiters only.
- *Boundary sentinels (D2).* =(first lecture)= and =(last lecture)= are
  specified.
- *Provenance (E3).* The course =README.org= is authoritative; files MAY
  carry copies.
- *Captions (H3).* The requirement is stated in terms a linter can decide.
- *Tags (L1, L2).* Spelling is a grammar; "full words" is a SHOULD, because
  abbreviations cannot be checked mechanically. Hyphens are written as
  underscores in org tag position, where Org does not allow them.
- *Own-notes (M2).* They live in =lectures/= and follow the lecture rules.
- *Lint checks (O2).* Replaced by the rule table.
- *Clarified (D1, D3, D4, I3).* Heading text is exact; =definition= and
  =theorem= blocks require a name; =Recap= and =Concepts introduced= are
  second-level headings; the assignment slug is always =assignment=.

Added: R1, R2 (versioning and extensibility), C6, C7 (short-code parsing
and sequence order), E4, E5 (file and course metadata), F5, S1–S3, O3
(conformance levels), O4 (diagnostics), the grammars in File naming, and
the Reserved section.

Moved out of the protocol: the script listing (tooling is not part of the
protocol), the status prose, and the known Typst conversion limitations
(now in the repository README).

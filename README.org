#+title: Consistent lecture notes — Conversion Pipeline & Protocol
#+startup: overview

Lecture notes published online come in many shapes: a LaTeX project, a
Jupyter Book, an mdBook, a folder of Markdown. Each has its own idea of
where a lecture lives, how lectures are ordered, where figures go, and
how pages link to each other. This project defines /one/ target
structure and provides deterministic tools to convert those sources
into it. (hopefully without losing any information)
 
The result is a course tree with one file per lecture, the same
sections and properties in every file, a consistent place for
attachments, and links by stable ID, regardless of what the upstream
looked like.

At this stage, this repository tracks only the conversion tooling,
protocol specification, and licence-auditing scripts. Converted course
trees are excluded via =.gitignore= until individual courses have been
cleaned, verified for free/open licensing, and checked for upstream
attribution.

* Supported upstream formats
 
Jupyter Book, mdBook, LaTeX and Markdown. =protocol/source-formats.org=
documents the structure of the upstream layouts (not governed by the
protocol), such as where ordering lives:
 
+ Jupyter Book: =_toc.yml=
+ mdBook: =src/SUMMARY.md=
+ Markdown converted from notebooks by =scripts/nb2md.py=: no manifest;
  order is implicit in file names.
+ LaTeX files

* Repository layout

+ The protocol files — When I said it defines /one/ target, this
  wasn't precisely true. Since the output is plain text files,
  in simple directories, there are protocol files for both
  org-mode and markdown files, using their native attachments,
  frontmatter, sections, and inline-maths.
  These files are found in =protocol/=.

+ Conversion scripts - This repo contains a set of Pandoc wrappers,
  with lua filters and Python post-processing, that convert the files
  into the protocol structure. The conversion is fully deterministic,
  meaning they could (with some work) be reversed, to make everything
  follow some other protocol.

+ The linter (=scripts/lint.py=) — A validator enforcing the protocol rules across
  generated =.org= files. /md is still WIP/
  
+ =scripts/ingest.sh= — Convert, lint, and index a single course.

+ =scripts/sync.sh= — Idempotently convert, lint, and index all courses
  in the workspace, skipping any that are already lint-clean.

+ (=scripts/gen_courses_org.py= and =scripts/gen_project_index.py)= — Are an
  automated system which generates a courses.org and index.org files, which
  compile lecture properties, without the need for _toc.yml or SUMMARY.md.
  Upstream LICENSE*, COPYING*, and metadata files are also used to manage
  =.gitignore= exclusions.

+ =TODO.org= — Open protocol and tooling tasks.
  
The org-mode form is the primary form-factor for the moment.
It is designed for my own Emacs setup using org-roam: every lecture and assignment
file is a roam node. A Markdown mirror (for example an Obsidian vault)
is planned but not yet implemented.

* A converted course
 
#+begin_example
physics/
└── super-duper-advanced-quantum-quantum-quantum/   <domain>/<course-slug>/
    ├── README.org      course metadata: name, short code, upstream URL, licence, status
    ├── source/         upstream material, verbatim
    ├── org-mode/       the wiki form
    │   ├── index.org       generated table of contents
    │   ├── lectures/       sdaQQQ-NN-slug.org
    │   ├── assignments/    optional; sdaQQQ-NN-assignment.org
    │   └── assets/
    │       ├── attachments/    figures, diagrams, images
    │       └── code/           code shipped with the course
    └── markdown/       markdown form
#+end_example
 
As shown in the example, the =source/= is verbatim, a frozen snapshot
of the upstream. They are not my words, so I do not feel I should
touch them in any way. There is no sync workflow: to update a course,
replace =source/= wholesale if you want to update it.

Courses are grouped by domain (=physics/=, =computing/=,
=mathematics/=, …). The project root also holds the generated
=index.org= and =courses.org=, and the controlled tag vocabulary in
=tags.org=.

* Brief Anatomy of a lecture file
 
** Naming
 
- =<short>-NN-slug.org=: the course's short code (declared in the course
  =README.org=), a zero-padded two-digit number, and a 1–5 word slug.
- Multi-part lectures use letter suffixes: =04a=, =04b=.
- The assignment for lecture NN is =<short>-NN-assignment.org=.
- Everything is lowercase, hyphenated, full words.
 
** Frontmatter
 
Every file carries at least:
 
#+begin_src org
:PROPERTIES:
:ID:           <org-id, also the org-roam id>
:COURSE:       <full course name>
:COURSE_SHORT: <short code>
:TYPE:         lecture | assignment | own-notes
:NUMBER:       <int, matching filename>
:PREV:         <id or empty>
:NEXT:         <id or empty>
:STATUS:       stub | draft | clean
:TAGS:         <space-separated tag list>
:END:
#+end_src
 
Or the markdown YAML equivalent.
 
** Sections
 
Every lecture has four top-level sections, in this order:
 
1. =Prev. lecture=: a human-visible rendering of the =:PREV:= link.
2. =Content=: the lecture body.
3. =Summary=: a recap (3–5 bullets) followed by the concepts introduced
   (one named concept per line, for later cross-linking).
   /These are not automatically generated, if the source lectures/
   /notes don't have them, they will be empty, pending handwriting./
4. =Next lecture=: a human-visible rendering of the =:NEXT:= link.
 
Prev/next appear both as properties (for tooling) and as sections (for
readers). Assignments use a different template:
+ Problem statement,
+ Solution (optional),
+ Reflection.
 
** Body conventions
 
- *Definitions, theorems, proofs* use custom blocks:
  =#+BEGIN_definition <name>=, =#+BEGIN_theorem <name>=,
  =#+BEGIN_proof <of what>=.
- *Code blocks* must name their language (=#+BEGIN_SRC rust=) and are
  executable with org-babel where sensible. =#+RESULTS= blocks are not
  stored. Larger code lives as files in =org-mode/assets/code/=.
- *Figures* live in =assets/attachments/= under descriptive names and are
  referenced by relative link:
  =[[file:../assets/attachments/feynman-diagram-tree-level.svg]]=. A
  =#+CAPTION:= is required for figures from externally licensed material.
- *No local PDFs.* External works are linked by URL only.
- *Links* between lectures use org-roam IDs (=[[id:…][…]]=); sections use
  =[[file:<path>::*Heading][…]]=; external resources are plain URLs.
  Cross-course links are allowed but discouraged.
- *Tags* come in two kinds: major tags from the controlled vocabulary in
  =tags.org= (domains, subjects, and file roles such as =exercise=,
  =reference=, =worked-example=) and free-form minor tags. All tags are
  lowercase, hyphenated, full words.

* Status levels
 
The =:STATUS:= property says how far along a file is. The planned
tiered linter (--level 0|1|2) maps onto it:
 
| =:STATUS:= | Lint level | Checks                                                                           |
|----------+------------+----------------------------------------------------------------------------------|
| stub     |          0 | Valid paths, required properties, consistent maths delimiters, local asset links |
| draft    |          1 | Level 0, plus required sections, (first lecture and last lecture) markers,       |
|          |            | Summary subsections, code block languages, tag spelling                          |
| clean    |          2 | Level 1, plus bidirectional =id:= links, major tags checked against =tags.org=,      |
|          |            | captions on externally licensed figures, no residual conversion macros           |
 
Tiered levels are not implemented yet; see =TODO.org=.
 
* Maths: LaTeX and Typst
 
The scripts are capable of converting LaTeX maths to Typst, if you
prefer its syntax (as do I). However, this conversion still loses
some native LaTeX information, such as function numbering, so it
is turned off by default.

- *LaTeX* (default): Pandoc emits native Org LaTeX maths.
- *Typst*: pass =--math-format typst= into the script and inline math
  will be written =$x^2$= (flush against the delimiters), and
  display math =$ x^2 $= (spaced).

* Requirements

+ Python 3.10+
+ =pandoc= on =PATH=
+ =git=

* Workflow

Place an upstream repository under =<domain>/<course-slug>/source/=.

Convert and validate a single course:
#+begin_src bash
./scripts/ingest.sh
#+end_src

Or run across the whole workspace:
#+begin_src bash
./scripts/sync.sh
#+end_src

By default, Pandoc emits native Org LaTeX math into
=<course>/org-latex/= and sets =:MATH_FORMAT: latex=. Pass
=--math-format typst= to emit Typst math (=:MATH_FORMAT: typst=)
instead. This will then be stored =<course>/org-latex/=.
/Note that the Typst maths conversion is still WIP./
/Not everything will be converted correctly,/
/and it will require manual cleanup./

*Markdown conversion is currently not handled yet.*

* Licensing & provenance

Every conversion injects the upstream author/origin, repository URL, and
detected licence into each page's =:PROPERTIES:= drawer and the course's
=README.org= via =scripts/convert/provenance.py=.

=scripts/gen_courses_org.py= enforces a fail-closed Git export policy:

  =block-all= (current default) — ignores all course content trees
  (=source/=, =org-mode/=, =markdown/=) as well as local =courses.org=
  and =index.org= files so only the tooling and protocol are tracked.

  =free-only= — tracks courses with verified free/open licences (e.g.,
  CC BY, CC BY-SA, CC0, MIT, Apache-2.0, GPL) while continuing to block
  =CC BY-NC=, =CC BY-ND=, personal notes, and unverified sources.
